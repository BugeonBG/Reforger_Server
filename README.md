# 리포저 서버 관리자 (RSM) v0.14.0

아르마3의 TADST처럼, **아르마 리포저 데디케이티드 서버**를 한국어 화면에서 설치하고 설정하고 켜고 끄는 Windows 프로그램입니다.

## 화면

어두운 올리브 계열 바탕에 앰버 강조색을 쓰는 다크 테마입니다. 왼쪽 사이드바 맨 위에 서버 상태 램프(실행 중/꺼짐)와 시작·중지 버튼이 있고, 그 아래 메뉴로 화면을 옮깁니다. 아래쪽 콘솔에는 서버와 SteamCMD 출력이 실시간으로 나옵니다.

- 글꼴: [Pretendard](https://github.com/orioncactus/pretendard) (SIL OFL 1.1)를 exe 안에 넣어 두어서 어느 PC에서나 같게 보입니다.
- 프로그램 아이콘: `src/RSM.App/Assets/app.ico` (16~256px). 작업 표시줄, Alt+Tab, exe 파일, 창 왼쪽 위 로고에 쓰입니다. 바꾸려면 이 파일만 교체하고 다시 빌드하세요.
- 메뉴 아이콘: Windows 기본 아이콘 글꼴(Segoe Fluent Icons / Segoe MDL2 Assets)
- 창 테두리와 제목 표시줄은 직접 그립니다(최소화/최대화/닫기 포함).
- 저장하지 않은 변경이 있으면 사이드바 아래 저장 버튼이 강조됩니다. **Ctrl+S**로도 저장됩니다.
- 처음 실행해서 서버가 아직 설치되지 않았으면 "서버 설치" 화면부터 열립니다.

## 할 수 있는 것

| 메뉴 | 기능 |
|---|---|
| 모드 자동 업데이트 | 켤 때와 10분~3시간마다 워크숍에서 모든 모드의 최신 버전 확인. 버전을 적어 둔 모드는 새 버전으로 바꿔 저장, 서버가 켜져 있으면 "접속자가 없을 때 재시작 / 바로 재시작 / 알리기만" 중 고른 대로 처리. 모드 목록에 "최신" 열 표시 |
| RSM 자동 업데이트 | 켤 때 GitHub 릴리스에 새 RSM이 있는지 확인 → 설치할지 묻고, 받아서(SHA-256 확인) RSM.exe를 바꾼 뒤 다시 켬. 설정·모드는 그대로. 사이드바에 "새 버전 설치" 버튼. 서버가 켜져 있으면 끄기 전에 물음 |
| 모드 완전 삭제 | 모드 목록에 "받은 파일"(서버 PC에 받은 버전·용량) 열과 휴지통 버튼. 휴지통은 목록에서 빼고 서버가 받은 모드 폴더(profile\\addons\\이름_ID)까지 지움(묻고 나서, 필요로 하는 다른 모드가 있으면 경고, 서버 실행 중엔 막음). "남은 파일 정리"는 목록에 없는 모드 폴더만 지움 |
| 접속 문제 | 입장하다 실패하거나 튕긴 플레이어를 서버 로그에서 찾아 "서버 현황 → 접속 문제"에 표시. 누가·언제·왜(끊김 코드 group/reason을 한국어로)와, 그 플레이어에게 그대로 보낼 안내문(해결 방법 포함)을 복사 버튼과 함께 보여줌. 정상적으로 나간 경우와 서버 종료는 빼고, 이름을 모르면 같은 IP로 접속했던 이름을 추정 |
| 로그 설명 | 콘솔의 "로그 설명"을 켜고 줄을 누르면 그 줄의 뜻·심각도(정상/참고/무시해도 됨/주의/문제)·할 일을 한국어로 설명. 아무 줄도 고르지 않으면 이번 실행 로그를 진단(게임 버전, 설정 파일, 받은 모드, 서버 등록, 접속 코드, 플레이어 입퇴장, 문제 목록). 인터넷 없이 프로그램 안의 규칙으로 동작 |
| 콘솔 (서버 로그) | 오류는 빨강, 경고는 주황, 서버 온라인·접속 코드·플레이어 접속·저장은 초록으로 표시. 전체 / 중요한 것만 / 경고·오류 / 오류만 필터와 검색, 글자 크기(가−/가+, Ctrl+휠), 고른 줄 또는 보이는 로그 복사(Ctrl+C), 창 전체로 크게 보기. 위로 스크롤해서 읽는 동안은 새 줄이 와도 화면이 내려가지 않고 "최신 로그로" 버튼이 뜸 |
| 서버 설치 | SteamCMD 자동 다운로드 → 서버 설치·업데이트(정식/실험 버전), 설치 여부 표시, **프로그램을 켤 때마다 새 서버 버전 확인 → 자동 업데이트**(끌 수 있음), 다른 곳에 설치된 서버 자동으로 찾기, Windows 방화벽 UDP 포트 열기(관리자 권한) |
| 서버 설정 | 서버 이름, 접속/관리자 비밀번호, 관리자 SteamID 목록, 최대 인원, 크로스플레이, 시나리오(공식 31개 한국어 이름 + 서버에서 워크숍 시나리오 불러오기), 포트, RCON, 시야 거리, 3인칭, BattlEye |
| 서버 현황 | 2초마다 갱신: 접속 인원(현재/최대)과 접속 중인 플레이어·접속 시간, 서버 CPU(PC 전체 CPU 같이), 서버 메모리(PC 전체 사용량 같이), 네트워크 업·다운로드 속도(이 PC 전체), 서버 이름·맵·가동 시간·스레드, 서버 FPS(`-logStats` 사용 시). 항목마다 최근 5분 그래프. 인원·서버 이름은 A2S 포트로 서버에 직접 조회 |
| 모드 | 모드 ID나 워크숍 링크로 추가(링크면 이름도 자동), 게임 모드 매니저의 JSON 탭 / 다른 서버 config.json / ID 목록을 한꺼번에 붙여넣기, **필요 모드(의존성) 자동 확인** — 모드를 넣으면 워크숍에서 그 모드가 필요로 하는 모드를 끝까지 따라가 찾고, 목록에 없는 것을 보여주며 같이 넣을지 묻습니다. "필요 모드 확인" 버튼으로 목록 전체도 다시 검사합니다. 표에서 바로 고치기, 워크숍 페이지 열기, JSON 복사. 목록에서 지우는 버튼은 없고, 쓰지 않을 모드는 체크를 풀어 비활성화합니다(내려받은 파일은 남아 있어 다시 체크하면 바로 씀) |
| 모드 활성화/비활성화 | 모드마다 체크칸: 체크하면 서버에서 활성화, 체크를 풀면 비활성화. "모두 활성화" / "모두 비활성화" 버튼. 비활성 모드는 목록에 남지만 config.json에는 들어가지 않아 서버가 받지도 불러오지도 않음(비활성 목록은 `server.disabled-mods.json`에 따로 저장, 서버는 이 파일을 읽지 않음). 활성 모드에 필요한 모드가 비활성이면 서버 시작 전에 경고하고, "필요 모드 확인"이 활성화할지 물어봄 |
| 모드 목록 옮기기 | "목록 저장": 모든 모드의 ID·이름·버전·활성 여부를 `.json` 또는 메모장으로 읽히는 `.txt`로 저장. "목록 불러오기": 그 파일로 목록을 한 번에 복원(활성/비활성 그대로, 기존 목록이 있으면 바꾸기/더하기 선택). 새 PC에서는 불러오기 → 저장 → 서버 시작이면 서버가 활성 모드를 워크숍에서 한 번에 내려받음 |
| 워크숍 | 프로그램 안에서 워크숍 둘러보기. 처음엔 전체 모드(인기순), 카테고리(무기·차량·지형 등 16개)를 고르면 **카테고리별 구역**으로 나눠 보여줌. 이름 검색, 정렬(인기·구독자·최신·평점), 구역마다 "더 보기", 썸네일·제작자·용량·구독자·평점 표시, "추가" 한 번으로 서버 목록에 넣고 필요 모드도 확인, 이미 넣은 모드는 "추가됨" |
| 설정 파일 | config.json 열기·저장·다른 이름으로 저장, 프로필(로그) 폴더, 최대 FPS, 추가 실행 인자, 저장될 config.json 실시간 미리보기 |
| 사이드바 / 콘솔 | 서버 시작(시작 전에 자동 저장)/중지, 서버·SteamCMD 출력 실시간 표시, 로그 폴더 열기 |

그 밖에:
- 저장하기 전에 흔한 실수를 한국어로 알려줍니다 (포트 겹침, 비밀번호 공백, 잘못된 모드 ID, 중복 모드, 범위를 벗어난 값 등).
- config.json에 이 프로그램이 모르는 항목(`operating` 등)을 직접 넣어 두면, 프로그램에서 저장해도 **그대로 남습니다.**
- 경로 설정은 `%AppData%\RSM\settings.json`에 기억합니다.
- 프로그램을 닫으면 실행 중인 서버도 같이 종료됩니다(닫기 전에 물어봄).

## 실행 파일 만들기

PC에 **.NET 8 SDK**가 있어야 합니다. ([다운로드](https://dotnet.microsoft.com/download/dotnet/8.0) → SDK x64)

```
build.bat
```

더블클릭하면 .NET 8 SDK가 있는지 먼저 확인하고(없으면 받는 곳을 알려줌), 테스트를 돌린 뒤 `publish\RSM.exe` 하나를 만들고 그 폴더를 엽니다. 실패해도 창이 닫히지 않으니 에러 메시지를 확인할 수 있습니다. 이 exe는 .NET이 포함된 단일 파일이라 **다른 사람에게 exe만 줘도 실행됩니다.**

Visual Studio 2022에서 `RSM.sln`을 열고 `RSM.App`을 시작 프로젝트로 실행해도 됩니다.

창은 기본 1440×900으로 열리고(화면이 작으면 화면 크기에 맞춤), 마지막 창 크기·최대화 여부·콘솔 높이·글자 크기를 기억합니다. 콘솔과 화면 사이 경계를 끌어 콘솔 높이를 바꿀 수 있습니다.

## RSM 자동 업데이트 설정 (처음 한 번)

RSM은 GitHub 릴리스에서 새 버전을 받습니다. 저장소에 소스를 올리고 릴리스를 발행하면, GitHub가 Windows에서 RSM.exe를 빌드·테스트해서 그 릴리스에 붙입니다(`.github/workflows/release.yml`).

1. https://github.com 에 가입합니다.
2. 오른쪽 위 **+ → New repository** → 이름 `RSM`, **Public** 선택 → **Create repository**.
3. 새 저장소 화면의 **uploading an existing file**을 누르고, 압축을 푼 RSM 폴더 **안의 내용 전부**(`.github` 폴더 포함)를 끌어다 놓은 뒤 **Commit changes**.
4. 저장소 오른쪽 **Releases → Create a new release** → **Choose a tag**에 `v0.14.0` 입력 → **Create new tag** → 설명(바뀐 점)을 적고 **Publish release**.
5. **Actions** 탭에서 "Release"가 끝나기를 기다립니다(5분쯤). 끝나면 릴리스에 `RSM.exe`, `RSM.exe.sha256`이 붙습니다.
6. 그 `RSM.exe`를 한 번만 직접 받아 지금 쓰는 것과 바꿉니다. 이 exe에는 저장소 주소가 들어 있어서, 이후로는 RSM이 켤 때 알아서 확인합니다.

새 버전을 낼 때: 바뀐 소스를 저장소에 올리고(3번처럼 덮어쓰기), 더 높은 태그(예: `v0.15.0`)로 릴리스를 발행하면 끝입니다. 릴리스 설명은 RSM의 "업데이트할까요?" 창에 그대로 보입니다.

- build.bat으로 직접 만든 RSM.exe는 저장소 주소를 모르므로, '서버 설치' 화면의 **RSM 업데이트 → GitHub 저장소**에 `아이디/RSM`을 넣으면 됩니다.
- RSM.exe가 Program Files처럼 쓰기가 막힌 폴더에 있으면 스스로 바꿀 수 없습니다. 바탕화면이나 다른 폴더에 두세요.

## 처음 쓰는 순서

1. "서버 설치" 화면에서 설치 폴더를 정하고 **서버 설치** → 로그에 "서버 설치/업데이트가 끝났습니다"가 나올 때까지 기다리기 (수 GB)
2. "서버 설정" 화면에서 서버 이름, 관리자 비밀번호, 시나리오 고르기
3. 모드를 쓸 거면 "모드" 화면에서 추가
4. 사이드바의 **서버 시작**
5. 외부에서 접속하려면 "서버 설치" 화면의 **Windows 방화벽 열기**, 그리고 공유기에서 UDP 2001, 17777 포트포워딩

## 프로젝트 구조

```
RSM.sln
src/RSM.Core/          화면과 무관한 모든 로직 (net8.0) — 어느 OS에서나 빌드·테스트됨
  MainViewModel.cs       화면 상태와 모든 버튼 동작
  ServerConfigJson.cs    config.json 읽기/쓰기 (모르는 키 보존)
  ModListParser.cs       붙여넣은 모드 목록 해석
  ScenarioCatalog.cs     공식 시나리오 + -listScenarios 출력 해석
  SettingsValidator.cs   저장 전 검사
  ServerTools.cs         SteamCMD / 서버 / 방화벽 명령줄
  ProcessRunner.cs       콘솔 프로그램 실행 + 출력 수집
src/RSM.App/           WPF 화면 (net8.0-windows) — XAML과 대화상자만
  Themes/Theme.xaml      색, 글꼴, 버튼·입력칸·토글·콤보·표·스크롤바 스타일
  MainWindow.xaml        사이드바 + 화면 4개 + 콘솔
  Fonts/                 Pretendard (OFL)
tests/RSM.Core.Tests/  테스트 (dotnet run --project tests/RSM.Core.Tests)
```

화면 쪽(RSM.App)은 XAML 바인딩과 대화상자만 있고, 버튼이 하는 일은 전부 `MainViewModel`에 있어서 테스트로 검증됩니다.

## 검증 상태

| 부분 | 상태 |
|---|---|
| RSM.Core (로직 + ViewModel) | 경고 없이 빌드, 테스트 전부 통과. 필요 모드 확인은 실제 워크숍 페이지 구조(2026-10-29 확인)를 그대로 본뜬 가짜 페이지로 단계별 의존성, 확인창 예/아니오, 오프라인을 검증. 가짜 SteamCMD와 가짜 서버 실행 파일로 **설치 → 설정 편집 → 모드 가져오기 → 저장(수동 추가 키 보존 확인) → 시나리오 목록 불러오기 → 서버 시작/중지 → 닫기 확인**까지 실제로 돌려봄 |
| RSM.App (WPF 화면) | **아직 컴파일해 보지 못했습니다.** 작업 환경에 WPF 빌드 도구가 없어서, XAML 문법, 바인딩 이름, 리소스 이름, 이벤트 연결이 맞는지만 스크립트로 대조했습니다. 디자인은 같은 색과 글꼴로 만든 HTML 목업으로 확인했고, 실제 창은 Windows에서 처음 띄워 봐야 합니다. `build.bat`에서 에러가 나면 메시지를 그대로 알려주세요. |
| 실제 리포저 서버와 SteamCMD | Windows에서 실제로 돌려보지 않았습니다. 특히 아래는 실제 출력에 맞춰 조정이 필요할 수 있습니다. |

실제 환경에서 확인할 것:
- SteamCMD 성공 판정: 출력에 `Success! App '1874900' fully installed.` 줄이 있는지로 판단합니다. SteamCMD가 처음에 자기 자신만 업데이트하고 끝나면(종료 코드 7) 한 번 더 자동으로 실행합니다.
- 최신 빌드 확인: `app_info_print` 출력의 `"branches" → "public" → "buildid"`를 읽습니다. 빌드 번호 파일은 사용자 PC의 실제 appmanifest로 확인했습니다.
- 서버 로그가 로그 창에 나오는지: 서버가 콘솔(stdout)로 로그를 내보낸다고 가정했습니다. 안 나오면 "로그 폴더"의 `console.log`를 보면 됩니다.
- 서버에서 시나리오 불러오기: `-listScenarios`로 실행해 출력에서 `{GUID}경로.conf`를 찾고, 출력이 5초간 멈추면(최대 2분) 서버를 끕니다.
- 서버 중지는 지금은 프로세스를 바로 종료합니다(정상 종료 신호 아님).

## 서버 자동 업데이트는 어떻게 동작하나

게임이 업데이트되면 서버도 같은 버전이어야 접속됩니다. 그래서 프로그램을 켤 때마다:

1. 설치된 서버의 빌드 번호를 SteamCMD 기록(`steamapps\appmanifest_1874900.acf`의 `buildid`)에서 읽고
2. SteamCMD로 스팀에 최신 빌드 번호를 묻고(`+app_info_print 1874900`, 공개 브랜치의 `buildid`)
3. 다르면 바로 업데이트합니다. 바뀐 부분만 받으니 보통 몇 분이면 끝납니다.

- "서버 설치" 화면의 **자동 업데이트** 토글로 끌 수 있고, 끄면 빌드 번호만 보여줍니다. **지금 확인** 버튼으로 언제든 확인할 수 있고, 이때는 업데이트 전에 묻습니다.
- 서버가 켜져 있으면 업데이트하지 않고 "서버를 멈춘 뒤 업데이트하세요"라고만 알립니다.
- 인터넷이나 스팀이 안 되면 "업데이트 확인 실패"만 표시하고 넘어갑니다.

### 서버가 엉뚱한 폴더에 설치됐을 때

SteamCMD 폴더가 서버 폴더 **안**에 있으면(예: 서버 폴더 `E:\AR_SERVER`, SteamCMD `E:\AR_SERVER\steamcmd`) SteamCMD가 설치 위치 지정을 무시하고 `steamcmd\steamapps\common\Arma Reforger Server`에 설치합니다. 이제 프로그램이 그 위치를 찾아 "서버 폴더를 찾은 위치로 바꿀까요?"라고 묻습니다. **예**를 누르면 다시 받지 않고 바로 씁니다. 새로 설치한다면 두 폴더를 나란히 두세요(`E:\AR_SERVER\steamcmd`, `E:\AR_SERVER\server`).

## 모드 자동 업데이트는 어떻게 동작하나

리포저 서버는 **켜질 때만** 모드를 받습니다. 버전이 빈 모드는 그때의 최신, 버전을 적은 모드는 그 버전입니다. 그래서 프로그램은:

1. 프로그램을 켤 때와 정한 간격(기본 30분)마다 워크숍 페이지에서 각 모드의 최신 버전(`currentVersionNumber`)을 새로 읽습니다.
2. 버전을 적어 둔 모드가 뒤처졌으면 새 버전으로 바꾸고 config.json에 저장합니다(다른 설정을 저장하지 않은 상태면 바꾸기만 하고 저장은 사용자가). 게임 모드 매니저에서 가져온 목록은 버전이 다 적혀 있어서 이 단계가 중요합니다.
3. 서버가 켜져 있으면, 서버를 켤 때 쓴 버전과 비교해 뒤처진 모드가 있으면:
   - **접속자가 없을 때 재시작**(기본): 접속자 수(A2S)를 1분마다 보고 0명이 되면 재시작
   - **바로 재시작**: 접속자가 있어도 바로
   - **알리기만**: 로그와 상태줄에만 표시
4. "지금 확인" 버튼은 적용 전에 묻습니다.

접속자 수를 알 수 없으면(A2S 응답 없음) "접속자가 없을 때 재시작"은 계속 기다립니다.

## 접속 문제(끊김 코드)는 어떻게 판단하나

서버 로그에는 끊길 때 `ServerImpl event: disconnected (identity=0x…), group=G, reason=R`처럼 숫자만 남고, 플레이어 게임 화면에는 같은 숫자가 이름과 함께 나옵니다(`Kick cause code: group=4 'DATA', reason=1 'RDB_MISMATCH'`). RSM이 아는 코드(Bohemia 버그 게시판과 스팀 문의에서 확인한 것):

| 코드 | 뜻 | 보통 원인 |
|---|---|---|
| group=1 reason=3 CONNECTION_FAILURE | 연결 실패 | 플레이어 인터넷/VPN |
| group=1 reason=4 TIMEOUT | 응답 시간 초과 | 불안정한 인터넷, 로딩이 너무 김 |
| group=1 reason=9 SHUTDOWN | 연결 종료 | 정상 퇴장, 서버 종료 |
| group=1 reason=11 SERVER_UNREACHABLE | 서버에 닿지 못함 | 포트포워딩, IPv6/VPN, publicAddress |
| group=3 reason=3 GAME_RESTART_REQUIRED | BattlEye 재시작 요구 | 게임 재시작 |
| group=4 reason=1 RDB_MISMATCH | 모드 파일이 서버와 다름 | 플레이어 PC에 옛/깨진 모드 |
| group=4 reason=2 SCRIPT_MISMATCH | 모드 스크립트가 서버와 다름 | 모드/게임 버전 차이 |
| group=6 reason=0 KICK | 강퇴 | 관리자/투표 |

모르는 코드는 숫자 그대로 보여주고, 플레이어에게 게임 화면의 오류 문구를 캡처해 달라고 안내합니다. 게임 중이던 플레이어가 모르는 코드로 나가면 정상 퇴장으로 봅니다.

## 필요 모드 확인은 어떻게 동작하나

공식 워크숍 사이트(reforger.armaplatform.com/workshop/<모드 ID>)의 모드 페이지에는 그 모드의 필요 모드 목록(ID, 이름, 버전)이 데이터로 들어 있습니다. 프로그램은 그 페이지를 읽고, 필요 모드의 페이지도 차례로 읽어 더 아래 단계의 필요 모드까지 찾습니다(한 번에 최대 4개씩, 같은 모드는 한 번만).

- 공개 API가 아니라 웹사이트 데이터를 읽는 방식이라, Bohemia가 사이트 구조를 바꾸면 확인이 실패할 수 있습니다. 그때는 "워크숍 페이지 형식이 바뀌어…" 메시지가 나오고, 모드 추가 자체는 그대로 됩니다.
- 인터넷이 안 되면 확인만 건너뛰고 모드는 추가됩니다.
- 필요 모드는 버전을 비워 두어(최신) 추가합니다.
